# Hawkeye 硬體儲存成本估算（2026-11-06）

依我們在 gem5 用的參數（CRC2 預設值）估算硬體需要的位元數。模擬時有些欄位存成 64 bit（例如完整的 PC），這裡改用硬體實際需要的寬度計算。
LLC：2 MB、16-way、64 B 行，共 32,768 行、2,048 個 set。

## 我們的設定（2 MB LLC）

| 結構 | 參數 | 位元數 | 大小 |
|---|---|---|---|
| 每行的 RRPV | 32,768 行 × 3 bit | 98,304 | 12.0 KB |
| OPTgen occupancy vector | 64 個取樣 set × 128 格 × 4 bit | 32,768 | 4.0 KB |
| 取樣 set 的計時器 | 64 × 10 bit | 640 | 0.08 KB |
| Sampler | 2,800 項 × 33 bit（有效 1、部分 tag 8、PC 簽名 11、時間戳 10、LRU 3） | 92,400 | 11.3 KB |
| 預測器 | 2,048 項 × 5 bit | 10,240 | 1.25 KB |
| 取樣 set 中每行的 PC 簽名（反向訓練用） | 64 × 16 行 × 11 bit | 11,264 | 1.4 KB |
| **合計** | | 245,616 | **約 30.0 KB** |

說明：
- PC 簽名取 11 bit，因為預測器以 `crc(PC) % 2048` 索引。時間戳取 10 bit，對應 `timer_size = 1024`。
- 反向訓練只發生在取樣 set，所以只有這 64 個 set 的行需要存 PC 簽名。

## 與原論文比較

| 結構 | 原論文 Table 3 | 我們（CRC2 預設） |
|---|---|---|
| Sampler | 2,400 項 × 5 byte = 12 KB | 2,800 項 × 33 bit = 11.3 KB |
| Occupancy vector | 每 4 次存取一格，32 格 × 4 bit × 64 = 1 KB | 每次存取一格，128 格 × 4 bit × 64 = 4 KB |
| 預測器 | 8K 項 × 3 bit = 3 KB | 2K 項 × 5 bit = 1.25 KB |
| 每行 RRPV | 12 KB | 12 KB |
| 取樣 set 的 PC 簽名 | 未列 | 1.4 KB |
| **合計** | **28 KB** | **約 30.0 KB** |

兩者都在 CRC2 的 32 KB 預算內。原論文 Table 4 列出的其他策略：LRU 16 KB、DRRIP 8 KB、SHiP 14 KB。

## 其他 LLC 大小

只有每行的 RRPV 隨 LLC 大小變化；取樣 set 固定 64 個，其他結構不變（共 18,414 byte）。

| LLC | RRPV | 合計 |
|---|---|---|
| 1 MB | 6 KB | 約 24.0 KB |
| 2 MB | 12 KB | 約 30.0 KB |
| 4 MB | 24 KB | 約 42.0 KB |

## 實驗用的變體（預設關閉）

- **HawkeyeI**（指令行一律 friendly）：插入時直接看請求是不是指令抓取，不需要每行一個 bit。只有取樣 set 的行（1,024 bit）和 sampler 項（2,800 bit）要記「是否為指令」，約多 0.5 KB。
- **HawkeyeR / HawkeyeA**（L2 驅逐時刷新）：HawkeyeR 要在任何 set 用該行的 PC 做預測，所以每行都要存 PC 簽名，32,768 × 11 bit = 44 KB，成本很高。HawkeyeA 不需要額外狀態。
