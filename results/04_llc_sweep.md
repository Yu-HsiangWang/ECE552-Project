# LLC 大小掃描（2026-11-06）

設定與 [02_spec_main.md](02_spec_main.md) 相同，只改 LLC 大小：1 MB、2 MB（主實驗）、4 MB，都是 16-way。
Hawkeye 的 set 數跟著 LLC 變，取樣 set 固定 64 個，OPTgen 參數不變。DRRIP 每個策略固定 32 個取樣 set。
測項：mcf、xalancbmk、omnetpp（LLC 影響最大的三個；gcc、xz、deepsjeng 在 2 MB 時 MPKI 都低於 0.6）。
腳本：`gem5/scripts/run_llc_sweep.sh`（HawkeyeI 用 `POLICIES=HawkeyeI` 另外跑）。
原始數字：[04_llc_sweep.csv](04_llc_sweep.csv)，其中 2 MB 的列取自主實驗，與 `02_spec_main.csv` 相同。

## 觀察

- **mcf**：三種大小下 Hawkeye 的 IPC 都最高，LLC 越大優勢越明顯。4 MB 時 miss 少 10.8%、IPC 高 7.6%，其他策略的 IPC 最多只高 1.5%。1 MB 時 SHiP 的 miss 比 Hawkeye 少（+7.8% vs +6.3%），但 IPC 較低。
- **xalancbmk**：工作集介於 1 MB 和 4 MB 之間（LRU MPKI 4.74 → 0.52 → 0.15）。1 MB 和 2 MB 時 BRRIP 最好，Hawkeye 是贏 LRU 的策略中改善最少的。差距在資料 miss：1 MB 時 Hawkeye 的資料 miss 是 697,277，BRRIP 只有 434,128。HawkeyeI 只多改善 3–5 個百分點。4 MB 時工作集放得下，各策略都在 ±5% 內，IPC 沒有差別。
- **omnetpp**：三種大小都沒有策略贏 LRU。4 MB 時其他策略與 LRU 的差距都在 1% 內，只有 Hawkeye 多 9.9% miss。Hawkeye 多出的 miss 中，指令行占 71%（1 MB）、37%（2 MB）、34%（4 MB）。
- **HawkeyeI**：在三種大小下都把指令 miss 降到與 LRU 相當或更少，omnetpp 的損失從 −12.8% / −20.4% / −9.9% 縮小到 −4.1% / −11.6% / −5.6%。xalancbmk、omnetpp 的六個組合 IPC 都比 Hawkeye 高，mcf 與 Hawkeye 相差不到 0.02%。
  - 剩下的損失全在資料 miss。1 MB 時指令行一律保留反而讓資料 miss 略增（omnetpp 193,826 → 198,340），指令行占用了資料行的空間。
- **BRRIP、DRRIP 在 1 MB 的 omnetpp**：miss 是 LRU 的 3.1 倍和 2.1 倍，SRRIP 只多 5%。已確認 DRRIP 的 set dueling 設定在三種大小下一致（每個策略 32 個取樣 set），原因尚未分析。
- 硬體成本：Hawkeye 在 1 MB、4 MB 時約需 24 KB、42 KB（見 [03_hawkeye_storage.md](03_hawkeye_storage.md)）。
